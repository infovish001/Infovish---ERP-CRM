# M03 module framework and shared master data

Authorized by the user's continuation after M02 handoff on 2026-10-30. Refines PRD MOD/ORG and contacts/catalog dependencies, NFR-001/002/003/006/007/009/013, DEP-001 through DEP-005/007 and SAD sections 3–6/9. Labels here are acceptance scenarios, not invented PRD definitions. Architecture-lead decisions are made under the implementation mandate.

## Implemented baseline

Only code-bundled allowlisted Parties and Catalog modules run. Manifests carry version, framework compatibility, dependencies, migration paths and public contracts. Validate versions, dependency existence/cycles and declared contract imports. No uploaded code, marketplace or arbitrary hooks execute. Tenant module installation/schema versions are operator-controlled; owner/administrator with MFA can activate entitled installed modules or deactivate them without erasing data. Entitlements are platform-operator metadata, not browser-editable subscription billing. These two baseline modules are included for new/upgraded local tenants, initially disabled. Dependency activation/disable ordering is enforced. Permissions, entitlement and active state are rechecked at the use-case boundary, including jobs and public contracts.

Additive tenant upgrades verify database identity before migrations, serialize with an operator advisory lock, suspend the tenant during upgrades and record version only after migrations/grants succeed. Failure preserves data and leaves the tenant suspended for explicit retry/review. Existing M02 tenants can still use identity/organization; M03 routes require schema 2. New provisioning installs schema 2. No destructive schema rollback or fleet migration automation is introduced.

Parties owns company-scoped contacts/customer/supplier master identities: immutable generated number and company, name, optional email/phone, roles and active status. Email normalization supports duplicate warnings/rejection within a company without claiming fuzzy matching/merging. Catalog owns company-scoped products/services, immutable SKU/type/unit, variants with string attributes and optional explicit base-currency list price (NUMERIC 20,6 and decimal string JSON). SKU uniqueness includes variants. No taxes, discounts, conversions, stock balances or accounting rules. Contact/product/variant updates require an expected revision to reject lost updates. Deactivation preserves records. Member/auditor reads require explicit active company grants; all mutations require privileged MFA. Public contract DTOs return identifiers/immutable values and enforce the same boundaries, never private models.

Shared services provide company-scoped locked document counters, transactional idempotency (actor/company/operation/key + request hash, required on creates), pagination/search, revision conflicts, and a tenant-local transactional outbox. Master-data mutations atomically commit data, audit and versioned ID-only events. At-least-once Redis delivery records deduplicated receipts in an internal event journal; this is the actual M03 consumer, not a claim of downstream business workflows. Bound retry/backoff and dead-letter state; authorized administrators can inspect and replay failures. A crash after queue publication may duplicate delivery, which must be harmless. Worker execution revalidates actor/company/module permission. No contact PII or prices go in queue payloads. Periodic dispatch uses an operator-selected tenant and active actor, never an unauthenticated HTTP scheduler endpoint.

## Acceptance

- M03-MOD: malformed/incompatible/cyclic manifests rejected; built-in contracts/dependencies verified; unauthorized activation, entitlement revocation, disabled-module access and dependency disable conflicts denied.
- M03-UPGRADE: new tenant and existing schema-1 upgrade preserve organization data, verify identity, apply module migrations/grants idempotently, and retain restricted runtime privileges.
- M03-DATA: contact/product/variant create/read/update/deactivate works with validation, pagination/search and revision conflicts. Company/tenant mismatches and duplicate identifiers do not expose another scope. Decimal amounts preserve six places and never use binary float arithmetic.
- M03-SHARED: transaction rollback leaves no number/record/event/idempotency residue; matching retries replay the same result, conflicting reuse fails, and concurrent allocations remain unique through database locking.
- M03-EVENT: real Redis delivery, duplicate receipts, revoked actors/modules, exception cleanup, retry/dead-letter/replay and two-tenant boundaries verified. Diagnostics expose only authorized metadata.
- M03-OPS: full M02 regression plus M03 tests, frontend/static/API/boundary/dependency/secret checks, container build/tests and hosted CI pass. Inspect Figma before UI work and document any missing exact frames. Stop before M04.

Deferred: CRM, sales workflows, inventory, full price lists/currency conversion, fiscal/intercompany logic, fuzzy deduplication/merge, import/export, custom modules, third-party hooks, commercial billing, documents, external messaging, broad event subscribers and production scale/recovery certification.
