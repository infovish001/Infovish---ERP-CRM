# Foundation verification strategy

Unit/feature tests cover fail-closed tenant context, process health, dependency success/failure envelopes, sensitive-error omission, correlation header, Inertia component/props and production UI denial. Facade mocks verify response behavior only; they do not count as live PostgreSQL or Redis evidence.

Integration tests are opt-in locally with `RUN_INTEGRATION=1`, mandatory in CI, and reject any PostgreSQL database other than `infovish_test`. They exercise migrations, rollback/reapply, transactional write rollback, a real Redis connection and a uniquely named Redis queue job. Never use a production database, credentials or tenant data for tests. Skipped tests remain unverified.

Frontend checks use strict TypeScript, ESLint, a production asset build and interaction tests for dependency failure display, theme and responsive navigation controls. Browser inspection supplements these tests; WCAG 2.2 AA, keyboard/assistive-technology coverage and full browser compatibility remain later release gates.

Vitest uses `backend/vitest.config.ts` with the React transform only. The application build uses `backend/vite.config.ts`, including Laravel's asset/HMR integration. Tests must also pass with `CI=true`; do not disable Laravel's environment guard to make a test process behave like a development server.

Static boundary checks validate future module manifests and cross-module import seams. They cannot prove dynamic SQL or tenant isolation. M02 supplies actual isolation/authorization tests described in M02_REPORT; business milestones add invariant, concurrency and idempotency tests. No fake feature or test count should substitute for these gates.

GitHub Actions uses ephemeral PostgreSQL/Redis, mandatory integration tests, Composer/npm audits and Gitleaks CLI history scanning. A local command pass does not imply a hosted CI run passed. Record every required check as PASS, FAIL, BLOCKED or NOT RUN in M01_REPORT.md and retain commands and limitations.

M02 complete regression command: `./scripts/platform-local.ps1 Test`. Thirty backend tests include real per-tenant PostgreSQL roles/databases, duplicate record IDs, role/grant boundaries, CSRF, Fortify TOTP/recovery/session revocation, immutable audits and reused Redis worker cleanup. Fixture provisioning uses separate administrator credentials while application requests use a restricted role. Only `infovish_test` is allowed; never run concurrently against the same test role/database. Four frontend tests cover foundation behavior and role-aware organization interactions. Concurrent load, full accessibility and penetration testing remain separate gates.

M03 adds live module entitlements/lifecycle, public DTO boundaries, company-scoped contact/product/variant rules, exact decimal strings, idempotency/revision conflicts, transaction rollback, parallel subprocess numbering/retries, schema-1 upgrade preservation/failure, Redis outbox deduplication and savepoint/dead-letter recovery. A real HTTP cookie smoke test supplements the early-Fortify-session regression; mocked Inertia tests alone do not prove persisted browser sessions. Run the complete suite through the operator helper; no parallel suite may rotate the shared test runtime role. Final counts and hosted evidence belong in M03_REPORT.

M04 acceptance includes assigned member/auditor/company/tenant scope, duplicate IDs and emails, CSRF/MFA/module gates, exact probability-weighted estimates and rounding/unknown values, lifecycle/revisions/immutable history, activities/timezones, explicit customer conversion/retry/concurrency and injected downstream failure rollback across module contracts. Separate processes and real PostgreSQL/Redis exercise actual locks and journal delivery. A database-error privacy test verifies no SQL text/bindings are reported. CRM React interactions cover privilege controls, explicit conversion collision recovery, stable retry keys, exact displayed estimates and board/list states. Final host/container/browser/CI counts and limitations belong in M04_REPORT.

M05 adds real quote/order lifecycle, classification/rounding/overflow, stable retries/concurrency, rollback, frozen snapshots, schema-3 upgrade, PDF escaping/auth, company/tenant/role/MFA/module/CSRF and real Redis journal tests. Run Pint with a fresh cache for final acceptance to prevent stale local formatting results. Commercial release evidence remains in R1_RELEASE_GATES and M05_REPORT.

M06 adds balanced journal/period/control-account rules, immutable database guards including later balanced line extension, source invoice/bill posting, payment allocation/void, reconciliation/outstanding clearing/backdating, historical management reports, sourced tax particulars and retained PDF integrity. Separate processes exercise posting retries and overpayment races; injected ledger failure checks complete rollback of counters, snapshots, audit and outbox. Schema-4 upgrade preserves earlier modules and revoked entitlements. Actual PostgreSQL/Redis, role/company/tenant/MFA/CSRF checks, frontend behavior, browser/PDF visual review, container and hosted CI outcomes are recorded in M06_REPORT. Do not run host/container suites concurrently against the shared rotating test role.
