# ADR-023 Finance ledger and immutable subledgers

Selected for authorized M06 on 2026-10-31. Finance owns accounts, periods, mappings, journal drafts/posted ledger, invoices/bills, payment/void records, statement matches and PDF issuance records. Cross-module billing data comes from an immutable Sales public DTO; party identity uses Parties. No private persistence coupling or source order mutation.

Use explicit account mappings, cent decimal strings, one tenant lifecycle lock and idempotency; deferred PostgreSQL balance constraints supplement server validation. Posted rows are insert/select only. Reversals append opposite manual journals; payment voids append both ledger and subledger evidence. Do not reverse automatic documents through a manual endpoint or silently change outstanding balances. Period locks and finalized bank windows reject backdating. Company auditors read Finance; ordinary members cannot.

The user retained the request for internet-sourced Sri Lankan rules. Tax-invoice implementation targets ordinary domestic VAT18 and the reviewed October-2026 Gazette specification; unsupported special regimes and statutory corrections are explicit exclusions. Operator registration/supply/eligibility/account mappings are required, not inferred. Management reports do not claim IFRS/SLFRS certification or override recognition policies. [IFRS conceptual framework](https://www.ifrs.org/issued-standards/list-of-standards/conceptual-framework/?headerSearchOption=phrase) supplies statement-element context; M06_TAX_REVIEW records IRD sources.

Alternatives rejected: mutable posted lines lose traceability; floats lose precision; unrestricted manual control-account postings break allocation reports; guessed tax eligibility/auto chart creates legal/accounting assumptions; reconciliation plugs hide differences. Schema 5 is additive/operator-only and preserves older module access. Production throughput, independent assessment, statutory/localization review and coordinated backup recovery remain open release gates.
