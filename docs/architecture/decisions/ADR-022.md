# ADR-022 Sales snapshots and quote-to-order integrity

Selected for authorized M05 on 2026-10-30. Sales owns company tax profiles, quotations/lines, confirmed orders/lines and immutable history. Dependencies are public Parties, Catalog and CRM contracts. Quotes snapshot legal/customer/product/tax details; issue freezes content, conversion copies snapshots rather than repricing. Each quote produces one confirmed order under a lifecycle lock, permanent unique constraint and idempotent transaction. No inventory/accounting side effects.

Privileged MFA users mutate Sales; other members/auditors only read explicitly granted companies. Optional opportunity linkage preserves CRM contract authorization. Schema 4 is additive and operator-only; previous schemas remain supported for existing modules. Runtime cannot alter schema, modify immutable order/history rows, or change frozen quote content; database triggers supplement application checks.

Use BCMath strings for pricing, six-place inputs and explicit two-place half-up LKR line/VAT totals. Ordinary VAT18 and operator-classified zero/exempt/unregistered treatments use source-versioned policy; tax-inclusive/special/financial/SSCL regimes are excluded, not guessed. See M05_SPEC and SRI_LANKA_TAX_RULES. [PHP arbitrary-precision rounding](https://www.php.net/manual/en/function.bcround.php) and [Dompdf security guidance](https://github.com/dompdf/dompdf/wiki/Securing-dompdf) reviewed. Dompdf renders escaped fixed templates with remote, PHP and JavaScript execution disabled.

Rejected: mutable orders lose commercial traceability; private joins break ownership; client totals/floats lose integrity; automatic tax inference misstates liability; unreviewed public deployment fails release gates. Company-wide read permissions are explicit; record/field-level Sales teams remain future work. Tenant-wide lock throughput and production PDF capacity must be measured before scale. R1 release is gated separately from functional verification.
