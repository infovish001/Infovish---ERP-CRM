# Foundation security model

M01/M02 remain local development infrastructure. M02 implements authentication, tenant membership and organization authorization; production security readiness is not claimed. The foundation page is restricted to local/testing and contains only dependency state. Liveness/readiness responses deliberately omit hostnames, exception messages and secrets. Restrict probe access at the production edge; they do not authorize business access.

Tenant context fails closed without verified identity. M02 resolves exact registered hosts and revalidates lifecycle, active user/membership and session version on each request. Privileged roles require confirmed TOTP MFA. Roles and explicit company/branch grants constrain organization reads/writes and audit visibility. Separate tenant roles/databases verify their identity before access; context and connections are cleared on request/job completion and exceptions. Provisioning credentials belong only to operator/test processes. The platform runtime role cannot write tenant registry metadata or create databases/roles; tenant roles cannot create schema, connect across tenants or change audit history. Fortify supplies password confirmation, challenge/recovery and throttling. CSRF protects session-authenticated mutations. Field-level authorization and broader ABAC remain deferred. See ADR-019 and M02_REPORT for tests and limits; compromised platform code and database superusers remain inside the privileged trust boundary.

Development credentials and application keys are randomly generated in ignored `.env` files. CI has isolated ephemeral service credentials. Never copy either to production. Production requires TLS, secure cookies, trusted proxies/hosts, a managed secret store, rotation, redacted structured logs, backups, restoration drills and scoped security assessment. Do not log bodies, authorization headers, provider credentials or business personal data. JSON formatting alone does not redact arbitrary developer-supplied messages; review logging call sites.

The Docker development image runs as a non-root application user but contains development dependencies and the development server. PostgreSQL/Redis ports bind to loopback only. Redis licensing must be reviewed before commercial deployment. No production deployment workflow exists.

Dependency audits and secret scanning are configured in CI. Version tags should be locked to reviewed action/image digests before enabling release deployment. No secrets should be present in source. Future financial/inventory writes require approved domain rules, decimal precision, transactions, locking and idempotency; future AI and communications must preserve their separate trust boundaries.

M03 gates bundled module operations on exact installed version, entitlement, activation, actor/MFA and active company grants. Only separately credentialed operators change entitlements or run tenant/module DDL; runtime can change activation fields only. ID-only outbox jobs reauthorize dispatcher/original author and record redacted errors, with an internal deduplicated journal receipt. Creates require scoped idempotency and edits reject stale revisions. Host routing also renames an already-resolved session store so Fortify and ordinary routes issue/read the same host-only cookie. See ADR-020 and M03_REPORT for actual verification and remaining limits.

M04 adds an explicit CRM mutation permission: members access assigned records in granted active companies, auditors read company scope, and privileged MFA users configure/reassign/convert/reopen. Shared mutations retain their privileged default for other modules. Assignment and parent links are revalidated inside transactions; customer conversion uses Parties public contracts. CRM journal receipt validates an active original author and company membership, with privileged dispatchers, without replaying business actions. SQL exception reporting excludes raw query text, bindings and private database detail strings; only connection name/SQLSTATE are logged. APP_DEBUG remains false. See ADR-021 and M04_REPORT for verification/limits.

M05 Sales mutations remain privileged MFA only; granted-company member/auditor reads include company Sales documents. CRM opportunity links retain CRM record scope. Quotes/orders persist seller/customer/product/tax snapshots; PDF generation authorizes the company/document before rendering escaped fixed templates with remote/PHP/JavaScript disabled and private no-store downloads. No arbitrary templates/assets or public PDF URLs. Orders/history are immutable with restricted grants/triggers; issued quote content is frozen. Production security/localization/recovery/load remain separate R1 gates.
